# Store raw judgments keyed by item version, and derive labels in code

Each judgment is stored as the raw probability or probability distribution the model returned, keyed by the item, the hash of the evidence sent, the question and its version, and the model version. Yes-or-no labels, feeds and scores are computed in code and never stored. We chose this over storing thresholded labels because a judgment that was never stored cannot be asked again fairly later: a forecast asked after the meeting already sees the minutes. Raw probabilities also let us change a threshold or a weight without paying to ask the model again, and let us compare a new model version on the same stored evidence. The cost is more storage, and the evidence text for each item version must be kept so that "why was this item judged this way?" can always be answered.
